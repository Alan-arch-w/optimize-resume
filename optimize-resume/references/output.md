# 文件输出与版面验收

## 版式选择

用户明确指定的参考模板优先；没有指定时使用 `assets/reference-layout.docx`。制作前读取 [template-layout.md](template-layout.md)，保留既定视觉语言，内置模板根据内容量自适应字号与分级间距；禁止另用左对齐姓名、无分隔线的样式覆盖模板。模板只决定格式，不决定候选人事实。

将真实经历整理好之后再排版，不为填满页面添加内容。超页优先删重复、压缩低相关内容；经历多时允许两页。每个经历的标题与首条内容应同页，不留下只有一行的末页。不能为一页目标擅自合并不同项目或删除核心个人贡献。

简历成稿后按 `interview-prep.md` 自动生成独立面试准备材料，默认交付Markdown文件；不向简历DOCX或PDF中追加问答、练习提示或JD分析。用户明确只要简历时省略配套材料。

## 附带生成脚本

运行环境需要 Python 3 与 python-docx。缺依赖时先采用宿主已有的文档能力，或在允许的环境安装；无能力时交付完整文本。

默认内置模板：

`python scripts/render_resume.py resume.json /absolute/output/resume.docx --density auto`

用户明确提供外部DOCX模板：

`python scripts/render_resume.py resume.json /absolute/output/resume.docx --template /absolute/reference.docx`

内置版式默认中文微软雅黑、英文Arial，可用 `--font "微软雅黑" --latin-font Arial` 显式指定。外部模板改字体前先确认收件端可用性，不把服务器的自定义字体作为交付默认值。

JSON 示例（虚构数据，只说明结构）：

```json
{
  "name": "候选人示例",
  "contact": ["示例邮箱", "示例城市"],
  "target": "产品运营实习",
  "summary": [],
  "sections": [
    {"title": "教育经历", "items": [
      {"heading": "示例大学", "date": "2023.09–2027.06（预计）", "role": "信息管理｜本科在读", "bullets": []}
    ]},
    {"title": "项目经历", "items": [
      {"heading": "校园活动报名原型｜个人课程项目", "date": "2026.03–2026.05", "bullets": [{"label": "产品设计", "text": "根据已确认材料填写具体行动与交付物。"}]}
    ]},
    {"title": "技能", "items": [
      {"heading": "工具", "bullets": ["实际使用过的工具及应用场景。"]}
    ]}
  ]
}
```

`heading` 为机构或项目名，`date` 为独立右对齐时间，`role` 为真实岗位/学位/项目角色，`detail` 为可选简短说明。`summary` 和 `bullets` 均可使用字符串或 `{"label":"短标签","text":"已确认事实"}`；短标签加粗，正文常规字重。兼容旧字符串列表，但不再自动添加圆点。优先采用明确标签，不能替用户发明职责。

字段只放用户事实。草稿示例或占位符不可进入正式投递版。脚本按层级估算首轮密度，不做事实校验、JD匹配或PDF渲染。估算无法替代真实分页。渲染后运行 `python scripts/inspect_layout.py /absolute/output/resume.pdf`（需要PyMuPDF），查看页数、版心纵向占用、页底留白和复查标记；再结合截图用 `--scale 0..1` 调整并重新渲染。外部模板默认保持原格式，用户允许优化时加 `--adapt-template`。

## PDF 与核验

生成 DOCX 后，使用宿主可用的文档渲染器；有 LibreOffice 时可导出 PDF。若有 documents 技能，使用其 renderer。随后将 PDF 每页渲染成 PNG 并逐页查看；使用可用的 PDF 提取工具检查字符与阅读顺序。内置模板交付DOCX使用微软雅黑和Arial；外部模板继承其字体。区分收件端字体与服务器预览字体：服务器缺少微软雅黑时，使用字体配置别名映射到中文覆盖完整的字体，或制作仅供渲染的临时副本；不得将服务器专有字体名写入最终DOCX。替代字体会造成轻微字宽差异，检查换行、日期、页数与中文。字体安装与别名配置必须对实际渲染进程可见。即使能抽取中文，也必须目视确认中文可见。

验收：与指定模板视觉比对通过，姓名联系信息位置、章节蓝线、日期对齐及段内加粗一致；页面尺寸正确、无文字截断和重叠、无乱码、标题与首条同页、内容顺序正常、链接文字完整、字号可读、无占位符。内容重新编辑后再渲染。未能生成或检查的格式必须准确说明，不能宣称成功。

文件名采用“姓名_岗位_简历.docx/pdf”；公开展示版本使用代称并移除联系方式。只有用户要求公开展示时才另做脱敏版。默认不交付底稿、含个人信息的测试数据或渲染临时文件。


## WPS与Word兼容检查

- 使用真正的标准`.docx`文件，不用改扩展名代替格式转换。检查ZIP包无损坏，所有XML可解析，正文为正确Unicode文字。
- 对默认版式显式设置 `w:rFonts` 的 `ascii`、`hAnsi`、`cs` 与 `eastAsia`；中文为微软雅黑，西文为Arial，同时统一文档默认值、段落/字符样式、正文和字体表。清除残留的 `asciiTheme`、`hAnsiTheme`、`eastAsiaTheme`、`cstheme` 等冲突声明。不要只改可见段落字体。
- 保留标准段落、制表位及段落边框，不引入依赖某个Office版本的文字框、浮动艺术字或专有排版。检查字体表声明与实际引用一致。
- 重新读取生成DOCX，对比输入与输出段落文字；检查无替换字符、中文正常、联系方式未改变。再以可用引擎渲染、目视检查；若可实际运行WPS，再检查打开结果。
- WPS仍乱码时，先区分缺字方框、重叠错位与文字编码损坏；必要时请用户提供异常页面截图。不能将“已修正常见字体声明问题”说成“已在WPS验证通过”。
