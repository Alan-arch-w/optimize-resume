# 基于简历与JD的模块化面试准备

## 范围与准备顺序

使用最终交付版简历、已确认事实底稿、JD（如有）及用户补充的面试信息。根据岗位、年级、经验和面试阶段调整难度。没有JD时按目标岗位准备，不虚构公司要求。多个岗位版本分别准备，共用事实。

默认交付以下十个模块，不再以总共8题代替完整准备。先提供目录、与JD的对应关系和最先练习的P0题，再提供逐字稿和分模块问答。项目数量决定篇幅；通过去重和优先级控制长度，不通过省略自我介绍、项目稿或整类模块缩短。用户明确只要部分模块时遵循其范围。群面、编程白板、作品集评审、外语面试等依岗位和用户要求增补，不当作每个人都必经的轮次。

模块是准备材料的组织方式，不声称每家企业按同样次序或相同轮次面试。面试形式（电话、视频、单面、群面）、轮次（HR、业务、终面）与考察内容分别理解，不混成同一分类。

## 固定模块及问答交付

| 模块 | 默认内容 | 必须配套的回答 |
| --- | --- | --- |
| 1 自我介绍 | “请用1分钟介绍自己”“请用3分钟介绍自己”两题 | 两份独立、完整的口语逐字稿，按事实突出岗位相关经历；短版提炼主线，长版展开证据，不用重复句撑时长 |
| 2 项目与实习讲述 | 简历中每个独立项目均准备；实习按已确认的核心项目或职责准备，避免重复 | 每项约1分钟概述、约3分钟完整逐字稿；附项目要点卡和可展开的证据，不能只给STAR提纲 |
| 3 简历逐项深挖 | 每个核心项目4–6题，其他项目或经历2–3题；另核查教育、技能、时间线等2–3题 | 对应具体措辞、本人贡献、方法、选型依据、产出、数据口径、验证与复盘的逐题回答；不会做的技能不补写为已掌握 |
| 4 JD与岗位专业能力 | 默认4–6题，覆盖JD关键职责；无JD时注明通用岗位题 | 有内容的知识或方法回答，再联系真实经历；每项核心要求有题目或明确待准备项，避免全是名词解释 |
| 5 业务案例与情境分析 | 默认2–3题，贴近目标岗位工作 | 完整解题示范，包含必要澄清、合理假设、分析、取舍、验证；计算题有过程和检查，假设数字明确标注，不冒充真实业务数据 |
| 6 行为与协作 | 默认3–4题，覆盖协作分歧、困难/失败、主动学习或责任承担 | 真实事件的口语回答，可用STAR组织；故事不足时给有用的框架和待补事实，不虚构冲突或失败 |
| 7 求职动机与岗位匹配 | 默认3–4题，按情况覆盖为何岗位/公司、转行、优势与待提升处、职业规划 | 从已确认的动机与经历作答；公司背景依公开信息核验，个人认同不能由公司宣传反推；无公司时给公司定制框架 |
| 8 质疑与压力追问 | 默认3组，每组包含主问题及2轮递进追问 | 每一轮均有回应示范或待补框架；针对贡献、效果、能力差距等证据，不只列尖锐问题或泛泛建议“保持冷静” |
| 9 HR与实际安排 | 默认2–4题，按实际情况覆盖到岗、每周天数、时长、地点、离职/空档、薪酬 | 基于真实约束给完整答法；薪酬意愿未知时给协商表达和待补信息，不替用户报价；不同意的工作条件不代为承诺 |
| 10 反向提问与收尾 | 默认3–5个可向面试官提的问题，并准备一个简短收尾 | 每题有可直接说的提问稿、提问目的及条件式接话；雇主回答不可预知，不伪造标准答案或企业承诺 |

数量是基础范围，按实际证据和模块覆盖调整、合并重复题。不能为满足数量编造经历；模块确实缺少事实时保留对应问题、答题框架和简短缺口，说明补什么能写成完整答案。简单“待补充”不算完成整个模块。

## 自我介绍与项目逐字稿

1分钟稿可从约180–250个汉字起步，3分钟稿可从约550–750字起步，均为练习估算，结合停顿、术语和用户实测语速调整；不能只数汉字就称精确计时。事实偏少时自然缩短并说明适合的时长，不灌水凑满3分钟。

自我介绍围绕“当前背景 → 相关经验与能力证据 → 岗位联系”展开。项目完整稿围绕“服务对象与问题 → 本人责任 → 关键行动及真实选择依据 → 交付与效果 → 复盘/下一步”展开。段落用自然口语，不能把简历项目符号逐条朗读，也不机械读出STAR字母。

项目稿要解释怎么做，而不是只堆“做了调研、写了PRD、画了原型”。材料不支持的决策理由、成果和复盘不补成亲历。若核心项目缺失关键细节，先生成有依据的概述，再把长稿标为“待补事实的稿件框架”，列2–3个最关键问题；已知其他部分照常完成，不重启整轮简历采集。

每个项目附简短要点卡，记录目标用户、问题、本人职责、关键决策、产出/指标口径及证据位置。长短稿、深挖回答和压力回应使用同一事实，不能前后改变人数、角色、日期或上线状态。能自然引出后续深挖即可，不编造“伏笔”或夸张亮点。

## 逐题生成标准

内部建立“JD职责/简历表述 → 可用事实 → 题目 → 回答 → 缺口”映射，保证覆盖而非仅挑容易回答的问题。默认优先级P0为开场、最相关项目及关键差距，P1为补充练习。

除已规定单独格式的逐字稿与反向提问外，每题包含：

- **问题与考察点**：自然问法，简短说明对应JD要求或简历证据。
- **口语回答示范**：一般约120–220字，随问题复杂度调整；较长案例分清推理步骤。事实充分时必须给具体回答，不能只给方法名或空白模板。
- **追问与回应**：至少一个有针对性的追问并给简短回应；压力模块按完整三轮问答执行，不能只给追问不作答。
- **待补事实**：仅确有缺口时列出。将来源核查放在准备提示里，不塞进候选人口头回答。

区分已发生事实、通用知识、当前建议和假设情境。个人经历、数字、动机、技术取舍、协作冲突及失败事件均须有来源。未知不等于不存在，不能把“材料未提供”说成“本人没有”。回答先讲具体贡献，再在相关问题中简短交代必要边界；不在每题重复未上线、无数据，也不写“我没有提供过”“我不会冒充”等自证式话术。

专业题按岗位选择。例如产品岗可覆盖需求判断、竞品与优先级、指标与验证、产品体验；技术岗选实际JD对应的技术与设计；运营岗选内容、活动、用户、数据分析。不要把本技能固定成AI产品面试题库。涉及易变功能、政策、公司动态或不确定知识时核验可靠来源；不把简历上传到第三方评分服务。

## 压力模块的具体做法

把压力面作为可准备的提问方式，不声称所有企业都有独立压力轮次。围绕岗位相关证据提高追问强度，不以羞辱、人格贬低、歧视或隐私盘问营造压力。

可根据真实简历选以下质疑方向：项目没上线如何说明价值；团队成果中个人贡献是什么；指标归因和样本是否充分；为何选该方案而非替代方案；经验不足如何接手岗位；时间安排与JD不符如何沟通。简历不存在相应问题时不预设候选人有缺陷。

每组形成“质疑 → 回应 → 针对回应的追问 → 回应 → 进一步反问/约束变化 → 回应”。追问应承接上一轮答案，不能连续问三个无关问题。练习回应可先澄清质疑、给证据、说明取舍，最后给可执行的改进或验证思路；不要求无条件认错、逢问道歉或硬凑成功案例。

如果面试官的假设与事实不符，示范如何礼貌纠正并回到证据；实习安排不匹配时如实协商，不教候选人虚报时长或承诺无法履行的条件。遇到不会的问题，提供澄清、说明已知与推理路径的自然答法，而不是编造实操经验。

## 交付、校验与更新

默认独立保存为“姓名_目标岗位_面试准备.md”，正文含目录、准备优先级、十模块内容及简短待补清单，按宿主持久保存机制交付。用户要求Word/PDF时使用相应文档能力。正文长时可按模块拆成有清晰索引的文件；不因篇幅长只交目录或题目，不把问答加入投递简历。

开头注明目标岗位、是否有JD、所依据的简历版本，以及材料为模拟练习题与示范。脚本便于练习组织，不要求死记硬背，不声称是企业真题或标准答案。对话先给简历与面试材料链接，再概括2–3个准备重点，避免整份长文重复粘贴。

交付前检查：十模块齐全或明确适配原因；1分钟与3分钟自我介绍均有；每个列出项目有讲述稿与深挖问答；普通题和每轮压力追问都有回答；反向提问有提问稿而非虚构雇主答复；JD关键职责得到覆盖；全文事实、角色、日期、指标及承诺一致；未确认内容没有变成确定陈述。仅排版修改不重做问答；简历事实、项目或JD改变时同步更新对应部分。

交付后可邀请逐题模拟面试，用户选择后再启动问答。模拟时一次问一题、等待用户回答、给针对性反馈和更自然的示范，再进入下一题；压力模拟先简短说明将进行递进质疑，保持职业语气。材料的来源检验和固定模块要求见 [interview-sources.md](interview-sources.md)。
